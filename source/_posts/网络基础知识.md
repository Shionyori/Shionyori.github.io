在开始网络编程之前，我们需要了解一些基础的网络知识，包括网络的分类、网关与路由、物理地址与网络地址、域名系统（DNS）、NAT 网络模式、内网与外网、本地回环地址以及物理服务器与 ESXi 虚拟平台。

# 网络的分类

- 按照覆盖范围，可以分为：
    个人区域网络（PAN）、局域网（LAN）、城域网（MAN）、广域网（WAN）
- 局域网又可以按照是否有线分为：
    - **以太网**，又称有线局域网
    - **WLAN**，又名无线局域网（其中一种被广泛采用的标准是WiFi）
    - 二者的主要区别在与是否有线，以及因此导致的传输速度、稳定性等特性的不同

# 网关与路由

## 路由器（Router）

- 主要作用：**转发数据包**
- 特点：
    - 可以连接多个网络接口
    - 有自己的路由表，知道不同网络段的下一跳
    - 支持静态路由和动态路由协议（OSPF、BGP 等）
- 举例：
    - 家里的路由器把 `192.168.1.0/24` 内网发往 `10.0.0.0/24`
    - 校园网核心路由器把 `10.1.0.0/16` 发往 `10.2.0.0/16`

## 网关（Gateway）

网关，也就是在**不同网络之间进行数据转发**的设备或系统
- **物理层面的转发**（例如：光猫、电缆中继、调制解调器）
- **网络层及以上的转发**（例如：路由器、防火墙、VPN、代理服务器、三层交换机）

## 关系和区别

| 维度  | 路由器              | 网关                      |
| --- | ---------------- | ----------------------- |
| 定义  | 网络层设备，转发不同网络的数据包 | 本网络的出口，发送到其他网络的数据包通过它转发 |
| 范围  | 可以连接多个网络，做复杂路由   | 一般只代表本网络的默认出口           |
| 功能  | 查路由表，转发到下一跳      | 接收本网络发送的非本地流量，并转发出去     |
| 表现  | 网络设备             | 可以是路由器，也可以是主机或防火墙       |

{% note info %}
核心理解：**网关是逻辑概念（默认出口），路由器是物理设备**
路由器可以当作网关，但网关不一定是路由器（比如一台 Linux 主机也可以做网关）
{% endnote %}

# 物理地址与网络地址

## 物理地址（MAC）

例：`00:1A:2B:3C:4D:5E`
设备网卡自带的硬件编号，用来在**局域网（LAN）内部识别设备**
由厂商烧录，全球唯一，一般固定

## 网络地址（IP 地址）

例：`192.168.1.10`
用来跨网络通信，标识设备在**整个网络（Internet）中的位置**
动态分配（DHCP），网络内唯一，可随时变化

## 动态主机配置协议（DHCP）

DHCP，一种网络管理协议，用于动态管理用户IP地址。
DHCP服务器，专门用于处理IP地址管理任务的服务器（一般是家庭路由器，而企业可能有专门的服务器设备）。

工作流程主要包括四个阶段：
1. **发现（Discover）**：客户端以广播方式发送DHCP Discover报文，寻找DHCP服务器。
2. **提供（Offer）**：DHCP服务器接收到Discover报文后，选择一个可用的IP地址，并通过DHCP Offer报文回复客户端。
3. **请求（Request）**：客户端接收到Offer报文后，发送DHCP Request报文，申请使用提供的IP地址。
4. **确认（Ack）**：DHCP服务器接收到Request报文后，发送DHCP Ack报文，确认IP地址的分配。

最后客户端会收到
- 自己申请的 IP 地址
- 网关地址（一般是路由器的 IP）
- DNS 服务器（下一节中提到）地址

## 通信时如何协作

1. 当设备通信时，数据既包含 **IP 地址**（逻辑目标），也包含 **MAC 地址**（物理目标）
2. 在局域网中，通过 **ARP 协议** 把 IP 转换为 MAC
3. 路由器再根据 IP 地址，把数据转发到正确的网络

# 域名系统（DNS）

将**域名**（www.example.com）与**IP地址**（142.250.198.70）相互映射
DNS 的主要功能是**域名解析**，即将域名转换为 IP 地址。
1. 用户在浏览器中输入域名（如 www.example.com）
2. 客户端向本地 DNS 服务器发送查询请求。

>本地DNS服务器，即所在网络的DNS服务器

3. 如果本地 DNS 服务器有缓存记录，则直接返回 IP 地址。
4. 若无缓存，本地 DNS 服务器会递归查询根 DNS 服务器、顶级域名服务器（如 .com）、权威域名服务器，直到找到对应的 IP 地址。

>例如你从阿里云买了一个域名，那么别人访问该域名时DNS访问流程是
>本地DNS服务器 -> 运营商DNS服务器（如移动/电信）-> 权威DNS服务器（阿里云）

5. 最终，客户端使用返回的 IP 地址与目标服务器建立连接。

# NAT网络模式

NAT 是为了解决 IPv4 地址不够而出现的"地址共享技术"，让私网内多个设备共用一个公网IP

{% note info %}
**NAT（网络地址转换）**
- 将私有IP地址转换为主机的公共IP地址；
- 主机可以访问虚拟机，但虚拟机无法直接访问主机的其他网络接口
{% endnote %}

## 工作原理

在 NAT 模式下：
- 每个小电脑（虚拟机）有一个自己的私有 IP，比如：
    `WSL2 IP：172.25.64.123`
- 而你的宿主机（Windows）可能是：
    `Windows IP：192.168.1.10 （或公网 IP）`
当虚拟机访问互联网（比如 `curl google.com`）时：
1. 它发出请求（源地址：172.25.64.123）
2. 宿主机的 **NAT 模块** 接收并修改这个请求：
    `把源地址 172.25.64.123 替换为 192.168.1.10`
3. 外网服务器收到请求，回复给 `192.168.1.10`；
4. 宿主机再根据 NAT 映射表，把回复转发回虚拟机的 172.25.64.123。

```
在 WSL2（NAT 模式） 下，Linux 子系统运行在一个虚拟化的网络环境中。
宿主机（Windows）和 WSL 有 不同的 IP 地址。
因此，WSL 无法直接访问宿主机的 IP(127.0.0.1)
例如，Windows 上跑着代理软件（如 Clash、V2Ray、Fiddler、Charles）监听在 127.0.0.1:7890，  
但在 WSL2 中访问 127.0.0.1:7890 会失败
```

# 内网与外网

## 校园网的结构

- 校园网本质上也是**一个大型内网**
- 特点：
    1. **私有内网段**：学校内部设备（电脑、服务器、打印机、教学实验室）有私有 IP，比如 `10.x.x.x`、`192.168.x.x`
    2. **网关 / NAT**：通过出口路由器访问公网
    3. **路由控制**：内部网段之间可以互访，也可能有防火墙限制某些子网访问某些资源

## 为什么校园网能访问外部网站

- 校园网的出口路由器会做 **NAT / PAT（端口地址转换）**
    - 内网私有 IP → 公网 IP
    - 回来的响应通过路由器 NAT 转发回对应内网设备
- 因此内部设备访问外网是"透明"的，像直接连互联网一样
- 同时，校园网可能有防火墙和访问控制策略，限制某些端口或网站访问

## 内网和外网的关系

- **内部通信**：
    - 校园网内设备互访直接通过内网路由
    - 不经过公网
- **访问外部网站**：
    - 内网数据包通过 NAT 转发到公网
    - 返回的数据包再通过 NAT 回到内网设备
- **对用户透明**：
    - 用户只需要访问网址或 IP，不需要手动配置路由
    - TCP/IP 和 NAT 自动处理地址映射

## 关键理解

- **校园网 = 内网 + 公网出口**
- 内网部分负责局域通信
- 公网出口 + NAT 负责访问外部网站
- 一台完全隔离的机房电脑，如果不连校园网，也不能直接访问外部网站，也就不能利用校园网的出口

| 名称                                   | 定义                   | 特征/作用                   |
| ------------------------------------ | -------------------- | ----------------------- |
| **网络（Network）**                      | 由可互相通信的设备组成          | 范围不限，可以局部或全球            |
| **局域网（LAN, Local Area Network）**     | 小范围网络，通常在同一栋楼或实验室    | 高速、低延迟、地理范围小            |
| **内网 / 私有网络（Private Network）**       | 受控、私有 IP 的网络，不直接暴露公网 | 可包含局域网、企业网、校园网等         |
| **公网 / Internet**                    | 全球互联网络，IP 唯一可路由      | 任何可上网设备都可以互访（路由可达）      |
| **路由器（Router）**                      | 网络设备，在不同网络间转发数据包     | 根据路由表决定下一跳              |
| **网关（Gateway）**                      | 网络出口设备，负责转发非本地流量     | 网关是逻辑概念，可由路由器或主机实现      |
| **子网（Subnet）**                       | 内网划分的小网络段            | 用于组织、隔离、管理网络设备          |
| **NAT（Network Address Translation）** | 网络地址转换               | 内网 IP 映射到公网 IP，实现内网访问公网 |
| **交换机（Switch）**                      | 内网设备，用于局域网内通信        | 只负责局域网内部转发，不处理不同网段      |
| **防火墙（Firewall）**                    | 安全设备，控制网络访问          | 可在内网/外网之间限制访问、端口、协议     |
| **VPN（Virtual Private Network）**     | 虚拟专用网络               | 在公网或隔离网中建立安全的通信通道       |
| **反向代理（Reverse Proxy）**              | 内网设备代理外部请求           | 可以让外部/另一内网访问内部服务        |
| **端口映射 / 转发（Port Forwarding）**       | 将外部请求映射到内网设备         | 允许不同网段或公网访问内网特定服务       |

# 本地回环地址

`127.0.0.1` 是一个特殊的 IP 地址，称为 **本地回环地址（loopback address）**。  
它的作用是：
让计算机访问"自己"——不经过任何外部网络。
也就是说：
- 在你的 Windows 上访问 `127.0.0.1` → 访问的是 Windows 自己。
- 在 WSL（或任何虚拟机）中访问 `127.0.0.1` → 默认访问的是 **那台虚拟机自己**。

## Mirrored网络模式的改变

从 Windows 11 build 22621.2500 起，微软加入了 **Mirrored Networking（镜像网络模式）**。  
它的核心变化是：
WSL 和 Windows 共用同一个网络栈，包括 localhost 回环接口。
也就是说：
- WSL 的 `127.0.0.1` **不再是虚拟机自己的**；
- 而是被镜像到 Windows 宿主机的 `127.0.0.1`； 
- 因此 WSL 访问 `127.0.0.1:7890` 时，实际上就是在访问 Windows 的本地服务。

# 物理服务器与ESXi虚拟平台

我们一般不会直接在服务器上部署程序，而是在服务器中划分多个虚拟机，然后在不同的虚拟机中部署不同的服务。
这样的好处是可以隔离故障和快速回滚，同时合理进行资源分配。

目前最常见的是在物理服务器上安装 VMware ESXi，它是一种专门为虚拟化设计的裸金属管理程序（不运行虚拟化层，直接在逻辑硬件执行指令），提供了一个可以远程访问的控制面板，可以控制服务器上虚拟机的创建与运行。

## 如何操作虚拟机和部署程序

你必须通过 **远程方式**：
1. **ESXi 管理界面（vSphere Web Client）**
    - 用浏览器访问 ESXi 的 IP
    - 可以：
        - 创建/删除虚拟机
        - 启动/关机虚拟机
        - 打开虚拟机控制台（类似直接操作虚拟机的"显示器"）
2. **远程登录虚拟机内部**
    - 如果虚拟机是 Linux：用 **SSH** 远程登录
    - 如果虚拟机是 Windows：用 **远程桌面（RDP）**
    - 在虚拟机里执行部署操作（安装数据库、后端、前端、Nginx）
 总结：**你不会直接在服务器上操作程序，而是通过远程访问虚拟机来操作**。

# IP地址分类

公共地址类
- A类地址：`1.0.0.0 ~ 126.255.255.255`，默认子网掩码：`255.0.0.0`
- B类地址：`128.0.0.0 ~ 191.255.255.255`，默认子网掩码：`255.255.0.0`
- C类地址：`192.0.0.0 ~ 223.255.255.255`，默认子网掩码：`255.255.255.0`
- D类地址：`224.0.0.0 ~ 239.255.255.255`，主要用于多播
- E类地址：`240.0.0.0 ~ 255.255.255.254`，保留供未来使用

私有地址（不可用于公网）
- A类私有：`10.0.0.0 ~ 10.255.255.255`
- B类私有：`172.16.0.0 ~ 172.31.255.255`
- C类私有：`192.168.0.0 ~ 192.168.255.255`

特殊地址
- `127.0.0.1`：回环地址，用于本地测试
- `0.0.0.0`：表示当前主机
- `255.255.255.255`：限制广播地址（仅在本地子网内有效）

# 子网掩码和子网划分

**子网掩码**是一个32位二进制数，用于将IP地址分为**网络地址**和**主机地址**两部分。

子网掩码的每一位与IP地址的相应位进行**按位与**运算，例如：
IP地址：`192.168.1.10（11000000.10101000.00000001.00001010）`
子网掩码：`255.255.255.0（11111111.11111111.11111111.000000000）`
网络地址：`192.168.1.0（11000000.10101000.00000001.00000000）`，主机地址：`10 (00001010)`

子网掩码的常见类型：
- `/8（255.0.0.0）`：用于A类地址，前8位表示网络部分。
- `/16（255.255.0.0）`：用于B类地址，前16位表示网络部分。
- `/24（255.255.255.0）`：用于C类地址，前24位表示网络部分。

**子网划分**就是将一个网络划分成多个网络。

例如将 `192.168.1.0/24`（其中 `/24` 表明该IP地址的前24位为网络部分）划分为4个子网：

- `192.168.1.0/26` （主机地址范围：`192.168.1.1 - 192.168.1.62`）
- `192.168.1.64/26` （主机地址范围：`192.168.1.65 - 192.168.1.126`）
- `192.168.1.128/26` （主机地址范围：`192.168.1.129 - 192.168.1.190`）
- `192.168.1.192/26` （主机地址范围：`192.168.1.193 - 192.168.1.254`）

可见子网地址的网络部分增加了2位，对于二进制数来说，也就是增加了 2^2 = 4 个可用IP地址。

# HTTP错误码

- 1xx（信息性状态码）：表示接收的请求正在处理。
- 2xx（成功状态码）：表示请求正常处理完毕。
- 3xx（重定向状态码）：需要后续操作才能完成这一请求。
- 4xx（客户端错误状态码）：表示请求包含语法错误或无法完成。
- 5xx（服务器错误状态码）：服务器在处理请求的过程中发生了错误
