C++11 引入了移动语义，它是 C++ 语言在资源管理方面的一次重大革新。通过移动语义，可以更高效地管理资源，减少不必要的拷贝操作，从而提升程序的性能。

---

# 1. 左值与右值

在 C++98 时期，C++ 对于表达式的值类别划分非常纯粹，只分为左值（lvalue）和 右值（rvalue）：
- 左值：一个有名字、有确定内存地址的值，可以对它取地址，生命周期由其所在的作用域决定
- 右值：与左值相反，它是一个没有身份的临时值，无法对它取地址，在表达式结束后就会消失

# 2. 拷贝造成的额外开销

众所周知，当我们进行对象传递时，通常有两种选择：一个是浅拷贝（也就是传引用），另一个是深拷贝（也就是把整个对象包括其内部指针指向的内存全都复制一份）。
- 浅拷贝：滥用可能会导致多个对象共享同一内存区域，引发 Double-Free 或悬空指针等问题。
- 深拷贝：虽然没有上述问题，但是由于它会完全重新分配一块内存进行一比一复制，往往会带来更大的开销。

考虑以下常见的代码：
```cpp
std::vector<int> get_large_data() {
    std::vector<int> tmp = {1, 2, 3, ...};
    return tmp;
}

std::vector<int> data = get_large_data();
```

传统机制的缺陷：函数内部构造了一个局部对象 `tmp`，并在堆（Heap）上分配了一块巨大的动态内存。当 `data` 接收返回值时，系统死板地触发了**深拷贝**：
- 重新申请一块大小相等的新内存。
- 把 `tmp` 内存里的内容逐字节拷贝过去。
- 让 `data` 指向这块新内存。
- 随后，`tmp` 触发析构函数，将原本完好无损的旧内存当场释放。
明明是完全一样的内容，在“交接”过程中却多了一次高昂的资源申请和拷贝操作。

{% note info %}
为什么我们不能直接接管这个临时对象的资源呢？
如果能让 `data` 直接指向 `tmp` 已经构造好的内存区域，不就可以省去所有的额外开销了吗？
{% endnote %}

在 C++98 的框架下，我们想直接“接管资源”的想法会遇到两个无法逾越的底层障碍：
1. C++ 规定==非常量左值引用不能绑定到临时对象（右值）==，我们无法将 `data` 直接指向临时对象 `tmp`
2. 临时变量 `tmp` 的内存区域会被析构函数释放，即使我们能让 `data` 指向它，也会导致指针悬空

为了打破上述机制的限制，C++11 分别引入了右值引用和特殊成员函数（移动构造和移动赋值函数）。

# 3. 值类别

随着 C++11 引入了右值引用，值类别被进一步划分为三大类：左值、将亡值和纯右值。

```
		表达式 (Expressions)
		    /       \ 
	泛左值 (glvalue)   右值 (rvalue) 
        /       \       /       \ 
左值(lvalue)  将亡值(xvalue)  纯右值(prvalue)
```

主要看两条属性：
- 是否有身份：可以通过名字或指针找到它（或者说是否可以取地址）
- 是否可移动：其资源可以被安全地剥夺，不会引发逻辑错误

| 值类别           | 有身份 | 可移动 | 典型样例                                |
| ------------- | --- | --- | ----------------------------------- |
| 左值 (lvalue)   | 有   | 不可  | 变量名、返回左值引用的函数调用                     |
| 纯右值 (prvalue) | 无   | 可   | 字面量、非引用类型的函数返回值、临时对象                |
| 将亡值 (xvalue)  | 有   | 可   | 返回右值引用的函数调用、显式转换成的右值引用（`std::move`） |

涉及xvalue的四种情况：
1. 调用函数（无论是隐式还是显式）的结果，该函数的返回类型是对对象类型的右值引用
2. 对 对象类型的右值引用 进行强制转换
3. 类成员访问表达式，指定非引用类型的非静态数据成员，其中对象表达式是xvalue
4. 指向成员表达式的指针，其中第一个操作数是xvalue，第二个操作数是指向数据成员的指针

# 4. 右值引用

右值引用（`&&`）专门用于绑定即将销毁的临时对象（右值），且可写（非 const），解决了接收方无法操作、无法修改临时对象的问题。

- 返回右值引用的函数，值类别为 `xvalue`
```cpp
int a;
std::move(a); // 将亡值，xvalue
```

- `std::move()` 除了返回右值引用之外，不会做任何操作；本质就是一次**强制转化**
```cpp
template<typename T>
typename remove_reference<T>::type&& move(T&& t) { // T&& 万能引用
	return static_cast<typename remove_reference<T>::type&&>(t);	
}
```

- `xvalue` 本质上是左值，只不过是贴上了一个“语义”标签的左值
- 右值引用是可以绑定到 `xvalue` 或 `prvalue` 的引用；左值引用是必须绑定到 `lvalue` 的引用
- 绑定到对象上的左值/右值引用并没有本质区别，他们都是一个对象的名别；
```cpp
int a = 10;
int& ra = a;
int& rra = std::move(a);
cout << a << endl; // 10
ra = 11;
cout << a << endl; // 11
rra = 12;
cout << a << endl; // 12 本质上 ra、rra 操作的都是同一个对象
```

- 左值引用和右值引用的唯一区别在于==后者多了一个“语义”标签，借此它的构造函数可以根据不同的引用类型来实现不同的操作==（调用不同版本的构造函数）。
- 构造函数的调用者通过 `std::move(a)` 做出承诺：a的资源我不要了，你可以随意移动；构造函数的实现者看到参数是右值引用，就可以放心地将资源持有权转移

```cpp
std::vector<int> v {1, 2, 3, 4, 5};
std::vector<int> u = std::move(v); // 资源持有权转移给了 u
for(auto a : v) {
    std::cout << a; // v 不再持有资源，v 为空，不能再进行访问，此为未定义行为！
}
```

- 在实际工程中，当某个对象即将被销毁时（将亡值），我们才会对他的资源进行移动，所以我们必须保证移动操作后的对象处于可析构状态（即将指针置空，避免资源也被一并销毁）

# 5. 移动构造与移动赋值

利用右值引用的特权，类的内部可以实现全新的移动成员函数（移动构造函数、移动赋值函数）。通过移动成员函数，我们可以绕过析构函数，防止临时对象的资源被销毁，转而将资源转移给新对象。

具体机制如下：
- 新对象（`data`）调用移动构造函数，把自己的内部指针指向临时对象（`tmp`）已经构造好的那块内存
- 然后将临时对象（`tmp`）内部的指针改写为 `nullptr`
- 函数表达式结束时，系统依旧调用 `tmp` 的析构函数：析构函数内部照常执行 `delete[] data`
- 但由于此时指针变为 `nullptr`，所以实际执行的是 `delete[] nullptr` （在 C++ 中释放空指针被认为是安全的）

```cpp
class MyVector {
    int* data;
public:
    // 移动构造函数
    MyVector(MyVector&& tmp) {
        this->data = tmp.data;  // 1. 指针接管：新对象直接指向现成内存
        tmp.data = nullptr;     // 2. 将临时对象的指针置为空
    }
    
    // 移动赋值函数
    Vector& MyVector::operator=(MyVector&& tmp) {
	    this->data = tmp.data;
	    tmp.data = nullptr;
    }
    
    ~MyVector() {
        delete[] data;          // 3. tmp 析构时，执行 delete[] nullptr
    }
};
```

# 6. 万能引用

在 C++11 中，并不是所有的 `&&` 都代表右值引用。当 `&&` 出现在一个需要**类型推导**的上下文中时（比如模板参数推导 `T&&` 或 `auto&&`），它被称为万能引用。

```cpp
template<typename T>
void func(T&& param); // 这里的 T&& 是万能引用（既能接收左值，也能接收右值）
```

C++ 不允许出现引用的引用（如 `int& &&`），为了让泛型代码能编译通过，编译器制定了**引用折叠规则**：

- `& + & -> &`
- `& + && -> &`
- `&& + & -> &`
- `&& + && -> &&`

只要有左值引用参与，折叠结果一律变成左值引用；只有当全都是右值引用时，才会折叠成右值引用。

万能引用本质上就是折叠规则的具体应用：
- 传入左值，`T` 被推导为 `int&`，而 `int& &&` 会被折叠为 `int&`，即左值引用
- 传入右值，`T` 被推导为 `int`，而 `int &&` 会被折叠为 `int&&`，即右值引用

# 7. 完美转发

在 C++ 中，==一切具名的变量都是左值==。这意味着，即使一个函数的形参是右值引用（或者是接收了右值的万能引用），在函数内部，这个参数的名字本身是一个左值（因为它有名字、有确定地址）。

这个特性会导致一些问题：
```cpp
void base_func(int& x);  // 接收左值
void base_func(int&& x); // 接收右值

template<typename T>
void wrapper(T&& param) {
    base_func(param); // 致命问题：无论传入的是什么，这里的 param 都是一个左值！
}

int main() {
    wrapper(10); // 传入的是纯右值 10，wrapper内部的 param 却退化成了左值
}
```

在上面的代码中，虽然 `10` 是右值，但进入 `wrapper` 后，`param` 变成了左值。此时调用 `base_func(param)`，会错误地匹配到左值版本，也就是说右值属性在二级传递的过程中丢失了。

为了解决这个问题，C++11 引入了 `std::forward`，它的作用是根据模板参数 `T` 携带的推导信息，完美还原参数最初的左右值属性。
```cpp
template<typename T>
void wrapper(T&& param) {
    // 如果 param 进来时是右值，forward 会把它强转回右值
    // 如果 param 进来时是左值，forward 会保持它是左值
    base_func(std::forward<T>(param)); 
}
```
