本文从网络通信的基本要素入手，梳理从局域网到骨干网的完整通信原理。核心线索只有一个：一台设备的数据包，如何从家里走到世界的另一端，又如何在返回时精确找到自己。内容包括基础设备（网卡、交换机、路由器）、地址系统（IP、NAT、DNS）、家庭宽带接入（光猫/OLT/BRAS）、企业级接入（专线/IDC/反向代理）以及移动通信。

# 网络通信的基本要素

一次网络通信，从最底层往上，需要依次解决四个问题：物理上怎么连接、局域网内怎么找到目标、跨网络怎么转发、人类怎么记住地址。这些要素是后续所有章节的基础。

## 物理连接与 MAC 地址

- **物理层**：用一根线缆把两台设备的网卡连起来，通过电压高低传输 `0` 和 `1` 的比特流。
- **MAC 地址**：每块网卡出厂烧录一个全球唯一的 6 字节编号（如 `AA-BB-CC-00-00-01`），用来在局域网内识别设备。
- **数据帧**：规定发送顺序为"目标 MAC + 源 MAC + 数据"。接收方检查目标 MAC 是否是自己的，是则收下，否则丢弃。

此时只能连接两台设备，扩展性为零。

## 交换机与局域网

多台设备两两拉线不现实，于是引入中间设备：

- **集线器（Hub）**：把信号复制并广播给所有端口，会产生**冲突域**（多个设备同时发送信号会相互干扰）。
- **交换机（Switch）**：记录每个端口对应的 MAC 地址（MAC 地址表），只向目标端口转发，实现点对点精准投递。**局域网（LAN）诞生**。

但此时所有设备必须处于同一个广播域内，无法连接远处的设备。

## 路由器与跨网通信

- **IP 地址**：逻辑地址，由"网络号 + 主机号"组成（如 `192.168.1.5`），标识设备在整个互联网中的位置。
- **路由器（Router）**：连接两个网络，根据目标 IP 查路由表，决定下一跳。
- **网关（Gateway）**：本网络的默认出口，通常就是路由器在内网的接口。

跨网络传输时，**MAC 地址每经过一个路由器就会更换**（底层寻址逐跳变化），而 **IP 地址全程不变**（始终指向最终目标）。

## 域名与 DNS

- **域名**：用人类易记的名字（`google.com`）代替一串数字 IP。
- **DNS**：域名 → IP 的映射系统，查询是层层递归的过程：
  1. 浏览器 / 操作系统缓存 → 本地 DNS 服务器
  2. 本地 DNS → 根服务器 → 顶级域服务器（`.com`）→ 权威 DNS 服务器
  3. 权威 DNS 返回真实 IP，逐级缓存并回传

> DNS 找到的那个 IP，往往不是你设备本身的地址，而是你家路由器或运营商网关的地址。数据包先到达这个入口，再由 NAT 把数据转交给网内的具体设备。

{% note info %}
**核心理解：局域网靠 MAC 找设备，跨网络靠 IP 找网关，全球寻址靠 DNS 把域名翻译成 IP。**
{% endnote %}

## 网络设备的职责

| 设备/系统 | 角色 | 核心依据 |
| --- | --- | --- |
| 交换机 | 局域网内精准投递 | MAC 地址表 |
| 路由器 | 跨网络转发 | IP 路由表 |
| 网关 | 本网络的出口 | 默认路由 |
| DNS | 域名 → IP 的翻译 | 域名-IP 映射表 |
| 网卡 | 比特流与物理信号互译，持有 MAC | 出厂烧录 |

# 网卡与物理介质

## 网卡（NIC）

网卡是设备连接网络的第一块"对外接口"，承担两个职责：

1. **翻译**：把 CPU 的二进制数据编码成电 / 光 / 电磁信号；接收时反向解码还原。
2. **身份载体**：MAC 地址烧录在网卡 ROM 中。

物理上，网卡是一块 PCB 电路板，核心部件包括：

- **MAC 控制器**：逻辑翻译，封装 / 解封数据帧、处理 MAC 过滤、DMA 直接写内存。
- **PHY 芯片**：物理转换，把 `0/1` 调制成网线上的电压变化（内置放大器补偿信号衰减）。
- **射频前端（FEM，无线网卡特有）**：功率放大器 + 低噪声放大器，负责放大无线信号。

{% note info %}
信号接收同样是网卡的核心职责（发送 + 接收，即收发器 Transceiver）。天线、光模块只负责物理信号的传导，不参与逻辑处理，真正的解码 / 编码都在网卡芯片内部完成。
{% endnote %}

## 有线与无线

- **有线**靠电信号 / 光信号在实体介质中传播；**无线**靠电磁波在空气中传播。
- 无线协议（**CSMA/CA**）采用"先请求、再发送、后确认"的握手机制，效率天然低于有线（同样带宽下通常只有有线的 60%-70%）。
- **无线只解决"最后几米"**：出家门后，所有流量都会变成电 / 光信号钻进物理线缆。

> 无论 Wi-Fi、蓝牙还是 4G/5G，无线信号到了路由器或基站，都会转入物理线缆（网线、光纤、海底光缆）。全球骨干网络 100% 靠物理线缆。

# 公网 IP 与 NAT

## 公网 IP 与私有 IP

- **公网 IP**：全球唯一，由 ICANN 把大段地址分给运营商，运营商再逐级下发，用于在公网中定位设备所属的网络出口。
- **私有 IP**：`192.168.x.x`、`10.x.x.x`、`172.16.x.x` 等，可在无数局域网中重复使用，但不会被路由到公网。

## NAT（网络地址转换）

IPv4 地址总数只有约 43 亿个，远不够全球设备使用。因此内网设备通过路由器做 **NAT**，多台设备共用同一个公网 IP：

1. 设备发数据（源 IP 为内网 `192.168.1.5:5555`）给路由器。
2. 路由器执行 **SNAT**：把源 IP 改写为 WAN 口公网 IP `6.6.6.6`，源端口改写为随机端口 `8888`，并记录一条映射。
3. 服务器回复时目标为 `6.6.6.6:8888`，路由器查 NAT 表，执行 **DNAT** 改回内网地址，精准送达。

{% note info %}
**NAT 表存在网关内存里，不在数据包里。** 数据包被改写后不保留任何内网痕迹，所有映射信息都保存在网关内存中。网关重启 → NAT 表清空 → 所有连接瞬间失效（所以重启路由器后已打开的网页都要重新加载）。
{% endnote %}

## CGNAT（运营商级 NAT）

运营商为了进一步节约 IPv4，在城域网部署 **CGNAT**，让成千上万用户共享极少数公网 IP：

- 你家路由器 WAN 口拿到的可能是运营商内网 IP（如 `100.64.1.2`），而非真正的公网 IP。
- 公网 IP（如 `6.6.6.6`）属于运营商机房的 CGNAT 网关；上网时才动态占用一个**端口**，闲置几分钟即回收。
- **公网 IP + 端口对应的是"一次通信请求"，而不是具体的设备**——同一台设备发两次请求，会得到两个不同的公网端口。

这带来一个关键后果：**外网无法主动访问内网设备**（NAT 表里没有对应的入站记录时，数据包直接被丢弃）。这也是家用宽带无法对外提供网站服务的根本原因。

数据包在"共享网络"下回家，要经过两段区分：

1. **CGNAT 网关**（公网 IP + 端口 → 运营商内网 IP）：公网 IP 是大家共用的，靠**端口号**查 NAT 表，找到你家路由器的运营商内网 IP（如 `100.64.1.2`）。
2. **BRAS**（运营商内网 IP → 物理路径）：BRAS 查会话表，把这个内网 IP 对应到你的宽带账号和物理线路。

{% note info %}
**共享网络下，区分靠"公网 IP + 端口"；进了运营商内网后，区分靠"运营商内网 IP 对应宽带账号"。** 两段各查各的表，链路才完整。常见的困惑就是把这两段混为一谈。
{% endnote %}

## 公网 IP 的指向

公网 IP 不指向你的电脑，也不指向某个具体的用户。它指向**运营商 BRAS 设备上的一个会话（Session）**。

运营商识别你的依据是三把"钥匙"：

1. **宽带账号（PPPoE 拨号）**：认证身份，建立会话。
2. **光猫 SN 序列号**：物理身份，绑定光纤端口。
3. **MAC 地址**：辅助身份，用于弱绑定校验。

这三把钥匙连同公网 IP 一起，被写进 BRAS 内存里的"会话表"，具体查表流程见后文「PPPoE 会话表」。

# 家庭宽带

家庭宽带是整条链路中最复杂的一段，通常被称为互联网的"最后一公里"。

## 物理链路

数据离开家庭路由器后，经过的链路是：

**光猫 → 入户光纤 → 分光器 → OLT（小区机房） → BRAS（运营商机房） → 骨干网**

| 路段 | 介质 | 关键设备 |
| --- | --- | --- |
| 电脑 → 路由器 | 空气（Wi-Fi） | 无线网卡、路由器（NAT） |
| 路由器 → 光猫 | 铜缆（网线） | 光猫（光电转换） |
| 光猫 → OLT | 光纤（光信号） | 分光器、OLT |
| OLT → BRAS | 城域光纤 | BRAS（认证、限速、映射） |
| BRAS → 骨干网 | 骨干光纤 | 核心路由器 |

## 光接入网设备

家庭宽带走的是光纤到户（FTTH），整段接入网由以下设备构成：

- **ONT（Optical Network Terminal，光网络终端）**：即家里的**光猫**，负责光电转换和 PPPoE 拨号。
- **ODN（Optical Distribution Network，光分配网络）**：OLT 与 ONT 之间的无源光纤网络，由光纤和**分光器（Splitter）**组成，把一根光纤的光信号分成 32/64 路连接到多个家庭。
- **OLT（Optical Line Terminal，光线路终端）**：小区机房的局端设备，接收光猫的光信号并汇聚成数据流，与上层 BRAS 对接。
- **BRAS（Broadband Remote Access Server，宽带远程接入服务器）**：运营商机房的接入设备，负责 PPPoE 认证、会话管理、限速与 IP 分配。

{% note info %}
**四者的关系**：ONT 在用户侧（光猫），OLT 在局端（小区机房），ODN 是两者之间无源的光纤链路（含分光器），BRAS 再往上接入骨干网。
{% endnote %}

## PPPoE 拨号与会话

- 光猫启动后通过 **PPPoE 拨号** 向 BRAS 发起认证，把宽带账号和密码交给 AAA 认证服务器。
- 认证通过后，BRAS 建立一个 **PPPoE 会话**，并从地址池分配一个 IP（可能是公网 IP，也可能是运营商内网 IP）。
- 只要不断线，会话就保持有效。**公网 IP 跟着会话走，而不是跟物理端口走**——搬家换光纤后重新拨号，就会绑定新的物理路径。

## PPPoE 会话表

公网 IP 不直接对应物理端口，也不直接对应宽带账号，而是对应 BRAS 内存里的一个**会话（Session）**。BRAS 的会话表把三样东西临时绑定在一起：

| 字段 | 含义 |
| --- | --- |
| 公网 IP | 分配给这次拨号的临时地址 |
| 宽带账号 | 用户的永久身份（如 `025-xxxx`） |
| 物理路径 | OLT 的 PON 口、分光器分支、光猫 SN |

当数据包从外网回来、目标是你的公网 IP 时，BRAS 的查找流程是：

1. 查会话表，找到该 IP 属于哪个宽带账号；
2. 根据账号查到对应的物理路径（哪个 OLT、哪根分光器下的哪个光猫）；
3. 给数据包打上 VLAN / 通道标签，交给 OLT 精确投递。

{% note info %}
**这就是"公网 IP 不指向你家光猫、数据却总能送到你家"的原因**：IP 对应的是 BRAS 内存里一条瞬时存在的绑定记录（会话表），它把 IP、账号、物理线路三者关联在一起。
{% endnote %}

## PON 的加密广播

一个 OLT 的 PON 口通过分光器分出 32/64 路，连接多个家庭光猫。**下行数据是广播的**（分光器下的所有光猫都能收到光信号），靠两层机制保证不串扰：

1. **逻辑通道标签（GEM Port ID）**：每个光猫分配唯一 ID，收到帧先看标签，不匹配直接丢弃。
2. **AES 加密密钥**：OLT 在注册阶段通过 OMCI 协议为每个光猫协商独立密钥；即使邻居"误收"，也解不开内容。

简单说：**逻辑通道标签决定光猫是否收下数据，加密密钥决定收下后能否解密**——前者保证精准投递，后者保证隐私。

> 数据从 BRAS 出发时，BRAS 只认 IP 查会话表，OLT 只认 VLAN / 通道标签找光猫——每一跳都只看自己需要的那层"标签"。

## 数据包的传播路线

以访问 `google.com` 为例：

1. **DNS 查询**：手机先向 DNS 服务器查询 `google.com` 对应的 IP。
2. **发包**：手机把源 IP（内网 `192.168.1.5`）和目标 IP 写入数据包，交给路由器。
3. **NAT**：路由器把源 IP 改为 WAN 口公网 IP，记录 NAT 表。
4. **出站**：数据包经光猫、OLT 到达 BRAS，BRAS 校验源 IP 会话合法后，直接放行到骨干网（不看目标 IP）。
5. **全球路由**：骨干网路由器根据目标 IP 逐级转发，经海底光缆到达对端机房。
6. **入站**：谷歌服务器回复，数据包目标为你的公网 IP。BRAS 查会话表找到你的宽带账号和物理路径。
7. **加密广播**：OLT 用你的光猫密钥加密，通过分光器广播，只有你的光猫能解密收下。
8. **反向 NAT**：路由器查 NAT 表，把目标 IP 改回 `192.168.1.5`，送达手机。

{% note info %}
**出站与入站，BRAS 的分工不同**：出站只看源 IP 是否属于合法会话；入站才查目标 IP 对应的会话和物理路径。
{% endnote %}

# 企业专线

## 家庭宽带与企业专线的区别

| 维度 | 家庭宽带 | 企业专线 / 托管 |
| --- | --- | --- |
| 带宽 | 共享、超卖、上下行不对等 | 独享、上下行对等、SLA 保障 |
| IP | 动态 / CGNAT 大内网 | 静态公网 IP，全球固定 |
| 认证 | PPPoE 拨号（办宽带） | 物理端口绑定 / BGP 互联 |
| 端口 | 80/443 默认封禁 | 全开放，可直接建站 |
| 网络层级 | 接入网（Access） | 汇聚 / 核心层（Core） |

企业服务器（如谷歌）**不经过 BRAS 和 PPPoE**：数据中心通过专线光纤直接接入运营商的骨干核心路由器，靠 **BGP 协议** 向全球宣告自己的 IP 段。两者的区别在于：家庭宽带需要逐户认证和计费（PPPoE 会话），企业专线则是物理直连、免认证的独立通道。

## 数据中心托管（IDC）

自己购买物理服务器后，有两条路：

- **托管到 IDC 机房**：把服务器放进专业数据中心，直连骨干网，获得固定公网 IP。本质上花钱买的是"进入骨干网的入场券"——IDC 已经铺好了到运营商骨干节点的光纤，并统一与运营商做 BGP 互联。你不需要懂 BGP，只需付带宽租用费。
- **放在家里**：走家庭宽带，需端口转发 + DDNS，且 80/443 被封，无法支撑正式对外服务。

> **云服务器 = "云上的托管"**：不购买硬件，按需付费，同样拥有固定公网 IP 和 BGP 多线接入。区别在于：托管需要自行采购并拥有服务器硬件，云服务器则是按需租用，无需关心硬件。

公网 IP 的分配是**批发与零售**的链条：ICANN → 运营商（一级批发）→ IDC / 云厂商（二级批发）→ 终端用户（零售）。IDC 从运营商手里承包整段 IP（如 `/24` 共 256 个），再拆成单个 IP 分给托管客户。

## 反向代理（Reverse Proxy）

**反向代理（Nginx 等）** 是"公网入口的调度员"：所有对外流量先到达代理服务器（唯一的公网 IP），代理根据 **域名（七层）** 或 **端口（四层）** 把请求转发给内网不同的服务。

- 访问 `www.a.com` → 转发给服务器 A
- 访问 `www.b.com` → 转发给服务器 B

{% note info %}
**无论学校（教育网）、企业（运营商专线）还是家庭，反向代理的工作模式完全一样**：它工作在应用层，只关心 HTTP 请求头里的域名（Host 字段），不关心底层的物理线路。这也是用少数几个公网 IP 承载成千上万服务的关键——一个入口 IP 后可以挂载任意数量的后端服务。
{% endnote %}

# 移动通信

## 蜂窝网络

移动通信的链路是：**手机 → 基站（4G/5G） → 回传网络 → PGW/UPF（运营商核心网） → 骨干网**。

- 身份识别靠 **SIM 卡（IMSI）**。
- 个人 SIM 卡走公共 IP 池，获得的是运营商内网 IP（`10.x.x.x` 等），通过 PGW 的 NAT 共享公网出口。
- 企业可通过 **APN / VPDN 专线** 购买专用 SIM 卡，获得独立固定 IP，数据直达企业内网，不经过公共互联网（物理上仍走公共基站，逻辑上走专属隧道）。

## 有线宽带与移动通信的关系

两者是**互补**关系，而非替代：

- **有线宽带**解决"固定地点的容量与稳定"：抗干扰强、时延低、带宽稳，适合机房、数据库、固定场所。
- **移动通信**解决"移动物体的连接与覆盖"：覆盖广、无需布线，但受基站负载和距离影响，时延抖动大。

企业两者都要：办公区用有线 + Wi-Fi；外勤设备、容灾备份用蜂窝网络（双线路故障转移）。

## 流量的本质与计费

- **技术上的"流量"**：数据包在物理介质（网线、光纤、空气）中的运动过程，是一个物理事件。
- **日常说的"流量"**：是运营商创造的商业名词，指"经过计费通道的数据总量"。

家庭宽带和手机流量走的是**两套物理隔离的接入网**（BRAS vs PGW），计费系统从入口就区分开了：宽带走固网计费（按宽带账号），移动走移动计费（按 SIM 卡 / APN），互不混淆。营业厅的"综合账单"只是月底把两个数据库的金额加在一起展示而已。

> 这也解释了"手机开热点给电脑用，下载扣的是手机流量而不是宽带包月"：数据包是从基站（移动接入网）进来的，跟光猫（固网接入网）毫无关系。

# CDN（内容分发网络）

**CDN（Content Delivery Network，内容分发网络）** 让互联网内容离用户更近，从而更快地加载。它由分布在全球各地的缓存节点组成，把网站的静态资源提前复制到离用户最近的节点上，用户请求时直接就近获取。

## 工作原理

1. 用户请求域名时，DNS 解析被交给 CDN 的智能调度系统。
2. CDN 根据用户 IP 判断地理位置和网络状况，返回离用户最近、负载最轻的节点的 IP。
3. 用户直接访问该节点：
   - **缓存命中**：节点上已有内容，直接返回。
   - **缓存未命中**：节点向源站请求一份，缓存到自己这里，再转发给用户。

{% note info %}
**DNS 与 CDN 的分工**：DNS 负责"告诉你去哪找"（域名 → IP），CDN 负责"在离你最近的地方把内容给你"。接入 CDN 后，DNS 解析返回的不再是源站 IP，而是最近的 CDN 节点 IP——这正是配置时要把域名解析改成 CNAME 指向 CDN 服务商的原因。
{% endnote %}

## 主要作用

- **提升访问速度**：用户就近获取内容，缩短数据传输的物理距离。
- **降低源站压力**：大部分请求由 CDN 节点响应，源站只处理少量请求。
- **增强稳定性**：分布式节点分摊流量，并能抵御 DDoS 攻击。
