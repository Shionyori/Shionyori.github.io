# 网络通信的基本要素

一次网络通信需要依次解决四个问题：物理上如何连接、局域网内如何找到目标设备、跨网络如何转发、如何把 IP 映射成易记的域名。

## 物理连接与 MAC 地址

- 物理层：用一根线缆连接两台设备的网卡，通过电压高低传输 `0` 和 `1` 的比特流。
- MAC 地址：每块网卡出厂烧录一个全球唯一的 6 字节编号（如 `AA-BB-CC-00-00-01`），用于在局域网内识别设备。
- 数据帧：按“目标 MAC + 源 MAC + 数据”的顺序封装。接收方检查目标 MAC 是否是自己，是则收下，否则丢弃。

这样只能连接两台设备，无法扩展到更多设备。

## 交换机与局域网

多台设备互相直连需要大量线缆，因此引入中间设备转发：

- 集线器（Hub）：把信号复制并广播到所有端口，多个设备同时发送时会产生冲突域，相互干扰。
- 交换机（Switch）：记录每个端口对应的 MAC 地址（MAC 地址表），只向目标端口转发数据，实现点对点通信，构成局域网（LAN）。

但交换机只能在同一广播域内转发，无法连接远处的设备。

## 路由器与跨网通信

- IP 地址：逻辑地址，由“网络号 + 主机号”组成（如 `192.168.1.5`），用于在整个互联网中标识设备。
- 路由器（Router）：连接两个网络，根据目标 IP 查路由表，决定下一跳。
- 网关（Gateway）：本网络的默认出口，通常是路由器在内网的接口。

跨网络传输时，MAC 地址每经过一个路由器就会更换（逐跳寻址），而 IP 地址全程不变（始终指向最终目标）。

## 域名与 DNS

- 域名：用易记的名字（`google.com`）代替数字形式的 IP。
- DNS：维护域名与 IP 的映射，查询过程逐级递归：
  1. 浏览器 / 操作系统缓存 → 本地 DNS 服务器
  2. 本地 DNS → 根服务器 → 顶级域服务器（`.com`）→ 权威 DNS 服务器
  3. 权威 DNS 返回真实 IP，各级逐级缓存并回传

> DNS 返回的 IP 往往不是目标设备的地址，而是该网络出口（路由器或运营商网关）的地址。数据包先到达出口，再由 NAT 转交给网内的具体设备。

{% note info %}
三层寻址的关系：局域网内用 MAC 找设备，跨网络用 IP 找网关，域名由 DNS 解析成 IP。
{% endnote %}

## 网络设备的职责

| 设备/系统 | 职责 | 依据 |
| --- | --- | --- |
| 交换机 | 局域网内按目标端口转发 | MAC 地址表 |
| 路由器 | 跨网络选择下一跳 | IP 路由表 |
| 网关 | 提供本网络出口 | 默认路由 |
| DNS | 域名解析为 IP | 域名-IP 映射表 |
| 网卡 | 在比特流与物理信号之间转换，持有 MAC | 出厂烧录 |

# 网卡与物理介质

## 网卡（NIC）

网卡负责两件事：

1. 编解码：把 CPU 的二进制数据编码成电 / 光 / 电磁信号发送；接收时反向解码还原。
2. 提供 MAC 地址：MAC 地址烧录在网卡 ROM 中，用于标识网卡。

物理上，网卡是一块 PCB 电路板，核心部件包括：

- MAC 控制器：负责数据帧的封装 / 解封、MAC 过滤，并通过 DMA 直接读写内存。
- PHY 芯片：把 `0/1` 调制成网线上的电压变化（内置放大器补偿信号衰减）。
- 射频前端（FEM，无线网卡才有）：功率放大器 + 低噪声放大器，用于放大无线信号。

{% note info %}
网卡同时负责发送和接收（收发器 Transceiver）。天线、光模块只完成物理信号的传导，编解码在网卡芯片内部完成。
{% endnote %}

## 有线与无线

- 有线靠电信号 / 光信号在实体介质中传播；无线靠电磁波在空气中传播。
- 无线协议（CSMA/CA）采用“先请求、再发送、后确认”的机制，效率低于有线（相同带宽下通常只有有线的 60%-70%）。
- 无线连接只覆盖设备到接入点这一段距离：离开这段距离后，数据一律通过网线、光纤等有线介质传输。

> Wi-Fi、蓝牙、4G/5G 的无线信号到达路由器或基站后，都会转入有线介质（网线、光纤、海底光缆）继续传输。骨干网络全部由物理线缆构成。

# 公网 IP 与 NAT

## 公网 IP 与私有 IP

- 公网 IP：全球唯一。ICANN 把地址段分给运营商，运营商再逐级向下分配，用于在公网中定位网络出口。
- 私有 IP：`192.168.x.x`、`10.x.x.x`、`172.16.x.x` 等，可在不同局域网中重复使用，但不会在公网中被路由。

## NAT（网络地址转换）

IPv4 地址总数约 43 亿，不够全球设备使用。内网设备通过路由器做 NAT，使多台设备共用一个公网 IP：

1. 设备发送数据包（源 IP 为内网 `192.168.1.5:5555`）给路由器。
2. 路由器执行 SNAT：把源 IP 改写为 WAN 口公网 IP `6.6.6.6`，源端口改写为随机端口 `8888`，并记录一条映射。
3. 服务器回复时目标为 `6.6.6.6:8888`，路由器查 NAT 表，执行 DNAT 把目标改回内网地址后转发。

{% note info %}
NAT 映射保存在网关内存中，不写入数据包。网关重启会清空 NAT 表，所有经过该网关的连接随即中断（所以重启路由器后，已打开的网页需要重新加载）。
{% endnote %}

## CGNAT（运营商级 NAT）

运营商在城域网部署 CGNAT，让大量用户共享少量公网 IP：

- 家庭路由器 WAN 口拿到的可能是运营商内网 IP（如 `100.64.1.2`），而不是公网 IP。
- 公网 IP（如 `6.6.6.6`）属于运营商机房的 CGNAT 网关；上网时动态占用一个端口，闲置几分钟后回收。
- 公网 IP + 端口与一次通信请求对应，不与设备绑定：同一设备发起两次请求，会获得两个不同的公网端口。

由此产生一个后果：外网无法主动访问内网设备——NAT 表中没有对应入站记录时，入站数据包会被丢弃。这是家庭宽带无法直接对外提供服务的原因。

数据包返回时，经过两层地址映射：

1. CGNAT 网关（公网 IP + 端口 → 运营商内网 IP）：按端口查 NAT 表，找到家庭路由器的运营商内网 IP（如 `100.64.1.2`）。
2. BRAS（运营商内网 IP → 物理路径）：查会话表，把运营商内网 IP 对应到宽带账号和物理线路。

{% note info %}
公网段按“公网 IP + 端口”区分用户，运营商内网段按“运营商内网 IP ↔ 宽带账号”区分用户。两层映射需要分别查询，链路才能完整。
{% endnote %}

## 公网 IP 的指向

公网 IP 不与某台电脑或某个用户固定绑定，而是指向运营商 BRAS 上的一条会话记录。BRAS 建立会话时记录以下信息：

1. 宽带账号（PPPoE 拨号）：用于认证。
2. 光猫 SN 序列号：标识物理光猫，绑定光纤端口。
3. MAC 地址：用于弱绑定校验。

BRAS 把公网 IP 与会话信息存入内存中的会话表，查询流程见后文「PPPoE 会话表」。

# 家庭宽带

家庭接入段设备多、协议层次多，下面按物理链路、接入设备、拨号与查表流程分别说明。

## 物理链路

数据离开家庭路由器后经过的链路：

光猫 → 入户光纤 → 分光器 → OLT（小区机房） → BRAS（运营商机房） → 骨干网

| 路段 | 介质 | 关键设备 |
| --- | --- | --- |
| 电脑 → 路由器 | 空气（Wi-Fi） | 无线网卡、路由器（NAT） |
| 路由器 → 光猫 | 铜缆（网线） | 光猫（光电转换） |
| 光猫 → OLT | 光纤（光信号） | 分光器、OLT |
| OLT → BRAS | 城域光纤 | BRAS（认证、限速、映射） |
| BRAS → 骨干网 | 骨干光纤 | 核心路由器 |

## 光接入网设备

家庭宽带采用光纤到户（FTTH），接入网由以下设备构成：

- ONT（Optical Network Terminal，光网络终端）：即家庭光猫，负责光电转换和 PPPoE 拨号。
- ODN（Optical Distribution Network，光分配网络）：OLT 与 ONT 之间的无源光纤网络，由光纤和分光器（Splitter）组成，把一根光纤的光信号分成 32/64 路连接到多个家庭。
- OLT（Optical Line Terminal，光线路终端）：小区机房的局端设备，接收光猫的光信号并汇聚成数据流，与上层 BRAS 对接。
- BRAS（Broadband Remote Access Server，宽带远程接入服务器）：运营商机房的接入设备，负责 PPPoE 认证、会话管理、限速与 IP 分配。

{% note info %}
设备位置：ONT 在用户侧（光猫），OLT 在局端（小区机房），ODN 是两者之间的无源光纤链路（含分光器），BRAS 再往上接入骨干网。
{% endnote %}

## PPPoE 拨号与会话

- 光猫启动后通过 PPPoE 拨号向 BRAS 发起认证，把宽带账号和密码交给 AAA 认证服务器。
- 认证通过后，BRAS 建立 PPPoE 会话，并从地址池分配一个 IP（可能是公网 IP，也可能是运营商内网 IP）。
- 会话在断线前持续有效。重新拨号后，IP 重新分配，并绑定新的物理路径（搬家更换光纤后需要重新拨号）。

## PPPoE 会话表

公网 IP 不与物理端口或宽带账号直接绑定，而是对应 BRAS 内存中的一条会话记录。BRAS 会话表临时绑定以下三项：

| 字段 | 含义 |
| --- | --- |
| 公网 IP | 分配给本次拨号的临时地址 |
| 宽带账号 | 用户的永久身份（如 `025-xxxx`） |
| 物理路径 | OLT 的 PON 口、分光器分支、光猫 SN |

外网数据包返回、目标为你的公网 IP 时，BRAS 的查询流程：

1. 查会话表，确定该 IP 属于哪个宽带账号；
2. 根据账号查到对应物理路径（哪个 OLT、哪根分光器下的哪个光猫）；
3. 给数据包打上 VLAN / 通道标签，交给 OLT 投递。

{% note info %}
数据包能够被送到家里，依据的是 BRAS 会话表中“公网 IP ↔ 宽带账号 ↔ 物理路径”的临时绑定，公网 IP 与光猫之间没有固定映射。
{% endnote %}

## PON 的加密广播

一个 OLT 的 PON 口通过分光器分出 32/64 路，连接多个家庭光猫。下行数据是广播的（分光器下的所有光猫都能收到光信号），靠两层机制保证只有目标光猫能收到并解开：

1. 逻辑通道标签（GEM Port ID）：每个光猫分配唯一 ID，收到帧先看标签，不匹配直接丢弃。
2. AES 加密密钥：OLT 在注册阶段通过 OMCI 协议与每个光猫协商独立密钥；其他光猫即使收到帧也无法解密。

标签负责过滤（决定是否收下数据），密钥负责解密（决定能否读取内容），两者职责不同。

> 各段设备只处理自己负责的那一层：BRAS 按 IP 查会话表，OLT 按 VLAN / GEM 标签选择光猫。

## 数据包的传播路线

以手机访问 `google.com` 为例：

1. DNS 查询：手机向 DNS 服务器查询 `google.com` 对应的 IP。
2. 发包：手机把源 IP（内网 `192.168.1.5`）和目标 IP 写入数据包，交给路由器。
3. NAT：路由器把源 IP 改为 WAN 口公网 IP，记录 NAT 表。
4. 出站：数据包经光猫、OLT 到达 BRAS，BRAS 校验源 IP 属于合法会话后放行到骨干网（不检查目标 IP）。
5. 全球路由：骨干网路由器按目标 IP 逐级转发，经海底光缆到达对端机房。
6. 入站：服务器回复，数据包目标为你的公网 IP。BRAS 查会话表，找到对应的宽带账号和物理路径。
7. 加密广播：OLT 用目标光猫的密钥加密，经分光器广播，只有该光猫能解密收下。
8. 反向 NAT：路由器查 NAT 表，把目标 IP 改回 `192.168.1.5`，送达手机。

{% note info %}
BRAS 在出站和入站时处理方式不同：出站只校验源 IP 是否属于合法会话；入站才查询目标 IP 对应的会话和物理路径。
{% endnote %}

# 企业专线

## 家庭宽带与企业专线的区别

| 维度 | 家庭宽带 | 企业专线 / 托管 |
| --- | --- | --- |
| 带宽 | 共享、超卖、上下行不对等 | 独享、上下行对等、SLA 保障 |
| IP | 动态 / CGNAT 大内网 | 静态公网 IP，全球固定 |
| 认证 | PPPoE 拨号（办宽带） | 物理端口绑定 / BGP 互联 |
| 端口 | 80/443 默认封禁 | 全开放，可直接建站 |
| 网络层级 | 接入网（Access） | 汇聚 / 核心层（Core） |

数据中心（如谷歌）不经过 BRAS 与 PPPoE：通过专线光纤直接接入运营商的骨干核心路由器，用 BGP 向全球宣告自己的 IP 段。家庭宽带需要逐用户认证与计费（PPPoE 会话），企业专线为物理直连，没有逐用户认证环节。

## 数据中心托管（IDC）

自行购买物理服务器后，有两种部署方式：

- 托管到 IDC 机房：把服务器放进数据中心。IDC 已铺设到运营商骨干节点的光纤，并与运营商建立 BGP 互联，托管客户按带宽付费即可获得固定公网 IP，无需自行与运营商对接 BGP。
- 放在家里：走家庭宽带，需要端口转发和 DDNS，且 80/443 默认被封，无法稳定对外提供服务。

> 云服务器与托管的区别在于资产归属：托管需要自行采购并持有服务器硬件；云服务器按需租用计算资源。两者同样提供固定公网 IP 与 BGP 接入。

公网 IP 按层级逐级分配：ICANN → 运营商 → IDC / 云厂商 → 终端用户。IDC 从运营商获取整段地址（如 `/24`，256 个），再拆分成单个 IP 分配给托管客户。

## 反向代理（Reverse Proxy）

反向代理（如 Nginx）持有公网 IP，接收所有对外流量，再根据请求的域名（七层）或端口（四层）转发给内网的不同服务：

- 访问 `www.a.com` → 转发给服务器 A
- 访问 `www.b.com` → 转发给服务器 B

{% note info %}
反向代理工作在应用层，依据 HTTP 请求中的 Host 字段转发，与底层的接入方式无关。一个公网入口可以挂载任意数量的后端服务，因此少量公网 IP 即可承载大量对外服务。
{% endnote %}

# 移动通信

## 蜂窝网络

移动通信的链路：手机 → 基站（4G/5G） → 回传网络 → PGW/UPF（运营商核心网） → 骨干网。

- 身份识别依据 SIM 卡中的 IMSI。
- 个人 SIM 卡接入公共 IP 池，获得运营商内网 IP（`10.x.x.x` 等），由 PGW 做 NAT，共享公网出口。
- 企业可购买 APN / VPDN 专线 SIM 卡，获得独立固定 IP。数据直达企业内网，不经过公共互联网（物理上仍走公共基站，逻辑上走专属隧道）。

## 有线宽带与移动通信

有线宽带与移动通信解决不同场景的问题，两者共用：

- 有线宽带：时延低、带宽稳定、抗干扰强，用于机房、数据库和固定场所。
- 移动通信：无需布线、覆盖范围大，用于移动设备；时延和带宽受基站负载、距离影响。

企业通常同时使用：办公区用有线 + Wi-Fi；外勤设备、容灾备份走蜂窝网络（两条线路互为备份）。

## 流量的口径与计费

- 技术口径的“流量”：数据包在物理介质（网线、光纤、空气）中传输的数据量。
- 计费口径的“流量”：运营商计费系统统计、经过计费通道的数据量。

家庭宽带与移动网络使用物理隔离的接入网（BRAS 与 PGW），从计费入口就已区分：宽带走固网计费（按宽带账号），移动走移动计费（按 SIM 卡 / APN）。两类费用在营业厅账单中合并展示，但底层数据相互独立。

> 手机开热点给电脑上网时，数据从基站（移动接入网）进入，消耗的是手机流量套餐，与家庭宽带计费无关。

# CDN（内容分发网络）

CDN（Content Delivery Network，内容分发网络）把网站的静态资源缓存到分布在全球各地的节点，用户请求时从最近的节点获取，缩短传输路径。

## 工作原理

1. 用户请求域名时，DNS 解析被交给 CDN 的调度系统。
2. CDN 根据用户 IP 判断地理位置和网络状况，返回离用户最近、负载最轻的节点的 IP。
3. 用户直接访问该节点：
   - 缓存命中：节点上已有内容，直接返回。
   - 缓存未命中：节点向源站请求一份内容，缓存后转发给用户。

{% note info %}
接入 CDN 后，DNS 解析返回的是 CDN 节点 IP，而不是源站 IP。配置时要把域名解析改为 CNAME，指向 CDN 服务商提供的域名。
{% endnote %}

## 主要作用

- 提升访问速度：用户就近获取内容，缩短数据传输路径。
- 降低源站压力：大部分请求由 CDN 节点响应，源站只处理少量请求。
- 增强稳定性：节点分布在不同网络，可分摊流量并抵御 DDoS 攻击。
