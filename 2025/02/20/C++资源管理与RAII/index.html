资源获取即初始化（RAII）是 C++ 最优雅的设计之一，把资源的生命周期绑定到栈对象的生命周期上，让析构函数替你打理一切，无需手动释放，也不会因异常而泄漏。

1. RAII 核心概念

1.1 什么是 RAII

RAII (Resource Acquisition Is Initialization)，即“资源获取即初始化”，或者叫作“由对象管理资源”。
核心思想： 利用栈对象的生命周期来管理资源的生命周期。

  • 资源获取 绑定到 对象构造
  • 资源释放 绑定到 对象析构

1.2 什么是资源

在C++中，资源指的是任何需要显式管理生命周期的东西。
例如常见资源有：

  • 堆内存（new / malloc）
  • 文件句柄（FILE* / fd）
  • 互斥量 (mutex / lock)
  • socket
  • 数据库连接
  • GPU / OS 资源
    其中最常见也是提到最多的就是堆内存的管理。

1.3 资源的所有权

谁负责释放资源，谁就是资源的所有者。
在 RAII 语境下，RAII 对象就是资源的所有者；当 RAII 对象销毁时，它负责释放其拥有的资源。

2. 生命周期绑定机制

2.1 对象的生命周期

RAII 生效的前提是管理对象必须是栈对象（局部变量）。
因为栈对象的生命周期由作用域管理，当作用域结束时，栈上的对象会被自动析构。

2.2 资源的生命周期

与栈对象不同，资源本身没有“自动析构”机制，它的生命周期必须依附于某个栈对象。当对象的生命周期结束时，对象会自动调用析构函数，然后由析构函数执行对资源的释放。
具体过程如下：

  • 构造时 RAII 对象获取资源（如 new）
  • 析构时 RAII 对象释放资源（如 delete）
  • 当对象离开作用域自动析构时，资源随之自动释放

2.3 异常安全

这是 RAII 相比手动管理资源（如 try-catch 中手动 delete）的最大优势。
具体行为如下：

  • 如果代码在持有资源期间抛出异常，C++ 会进行栈展开（Stack Unwinding）
  • 栈展开过程中，所有已构造的栈对象析构函数会被自动调用
    因此即使发生异常，RAII 对象也能保证资源被正确释放，不会泄漏。

3. RAII 的使用（Rule of Three / Five / Zero）

3.1 自己实现 RAII 类

三法则（The Rule of Three）
如果类需要自定义以下任一函数，通常需要全部自定义：

  • 析构函数 ~T()
  • 拷贝构造函数 T(const T&)
  • 拷贝赋值运算符 T& operator=(const T&)
    原因如下：
  • 资源释放：析构函数负责释放类中管理的资源，防止资源泄漏。
  • 深拷贝：拷贝构造函数和拷贝赋值运算符需要进行深拷贝，以避免资源共享和二次释放问题。

五法则（The Rule of Five）
C++11引入移动语义，需额外考虑：

  • 移动构造函数 T(T&&)
  • 移动赋值运算符 T& operator=(T&&)

3.2 使用标准库的 RAII 封装类

零法则（The Rule of Zero）

  • 不手动管理资源，尽可能使用标准库提供的 RAII 封装类
  • 避免实现析构/拷贝/移动函数，让编译器生成默认版本
    常见的 RAII 工具有：
  • std::unique_ptr / std::shared_ptr
  • std::vector
  • std::lock_guard
  • std::fstream

4. 拷贝操作中的资源转移

4.1 涉及拷贝的情况

拷贝会在以下情况发生：

  • 用已有对象给新对象赋值
  • 隐式转换时创建临时对象
  • 函数参数为类类型时创建临时对象
  • 函数返回值为类类型时创建临时对象

4.2 拷贝造成的资源所属权问题与解决方案

默认拷贝构造函数会进行浅拷贝，即将对象的每一项逐一复制，包括指针也只复制地址。

以最常见的资源——堆内存为例，由于指针存储的地址被直接复制给了其他对象，堆内存地址就会被多个对象所持有，即多个对象共享了同一份资源。浅拷贝往往会导致资源被多次释放（Double Free）。

解决方案：

  • 深拷贝：将资源也进行复制，让每个对象都占有一份资源
  • 移动语义：原对象放弃资源，转移所有权
  • 禁止拷贝：独占资源（std::unique_ptr，std::mutex）
